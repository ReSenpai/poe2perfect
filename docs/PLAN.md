# План реализации

Расширение для Chrome: страница билда PoE 2 на mobalytics.gg → чистый интерфейс по вкладкам.
Дизайн: [reference/DESIGN.md](../reference/DESIGN.md), схемы экранов: [reference/interface.md](../reference/interface.md).
Пример билда: https://mobalytics.gg/poe-2/builds/chaos-dot-lich-starter-deadrabbit

## Решения

| Вопрос | Решение |
|---|---|
| Стек | WXT + TypeScript (strict) + Preact + Vitest (+ happy-dom, @testing-library/preact) |
| Размещение | Поверх страницы сайта, в Shadow DOM, с переключателем «Оригинал ↔ Расширение» |
| Резисты и ES | Считаем по предметам и пассивкам, показываем с пометкой **beta** (значения приблизительные) |
| Параметры скиллов | Берём из справочника сайта (см. ниже) |
| Подсказки при наведении | Везде, как на сайте: предметы, руны/соул-коры, скиллы, саппорты, пассивки |
| Дерево пассивок | В первой версии — дерево самого сайта, встроенное во вкладку Passives |

## Источники данных

### 1. Билд — `window.__PRELOADED_STATE__` в HTML
Скрипт `window.__PRELOADED_STATE__={…};` (~590 КБ, валидный JSON).
Путь: `poe2State.apollo.graphqlV2.queries[]` → запрос с `queryKey[0] === "ngf-ug-featured-document-page"`
→ `state.data[0].game.documents.userGeneratedDocumentBySlug.data` (дальше — `doc`).

| Что | Где в `doc` |
|---|---|
| Название, патч | `data.name` (`"[0.5.5] ED Contagion Lich League Starter (…)"`) |
| Класс, асценданс, тип билда | `tags.data[]` по `groupSlug` (`class`, `ascendancy`, `build-type`…) |
| Автор, даты | `author`, `updatedAt` |
| Варианты (Act 1 … Endgame Low Life) | виджет `NgfDocumentCmWidgetContentVariantsV1` → `childrenVariants[]` (`id`, `title`, описание) |
| Экипировка варианта | `data.buildVariants.values[id].equipment` — слоты (`helmet`, `body`, `mainHand`, `offHand`, `leftRing`, `rightRing`, `amulet`, `belt`, `gloves`, `boots`, фласки, чармы) → `commonItem` (slug, имя, иконка, `isUnique`, моды) + `runes`; `priorityList` — список **предметов** |
| Скиллы варианта | `…skillGems.gems[]` → `activeSkill` (slug, имя, иконка) + `subSkills[]` (саппорты: slug и иконка) |
| Дерево пассивок | `…passiveTree` → `mainTree.selectedSlugs` (`node-51184`…), `set1Tree`, `set2Tree`, `ascendancyTree`, `jewels` |
| Тексты | виджеты `…RichTextSimplifiedV2` (Build Overview, How it Plays), описания Equipment/SkillGems (там приоритеты статов текстом), `…StrengthsAndWeaknessesV1`, видео |

Тексты — JSON редактора Lexical: абзацы, заголовки, списки, ссылки и встроенные «чипы» игровых сущностей
(`static-data-widget`: `id` = slug, `label`, `icon`, `groupId`).

### 2. Справочник — IndexedDB сайта `ngf-static-data`
Сайт сам кладёт туда полный справочник PoE 2 (~17.5 МБ, `cacheVersion`, TTL 7 дней).
Хранилище `cache`, запись с ключом `poe-2|<hash>` → `staticData.game.staticData`. Контент-скрипт работает
на том же домене и может читать эту базу. По ней работают подсказки сайта (при наведении запросов в сеть нет).

| Раздел | Что даёт |
|---|---|
| `poe2Gems` | имя, описание, теги, статы по уровням (каст, мана, требования), `bakedDescriptions` — для скиллов и саппортов |
| `poe2PassiveSkills` | ~10 000 пассивок: имя, иконка, `notable` / `keystone`, эффекты |
| `poe2PassiveSkillsGraph` | геометрия дерева: группы, орбиты, `node-N → passiveSlug`, рёбра |
| `poe2Armours`, `poe2Weapons`, `poe2Focuses`, `poe2Rings`, `poe2Amulets`… | предметы: базы, моды уникальных (диапазоны `(10-15)%`), требования |
| `poe2SoulCores`, `poe2Prefixes`, `poe2Suffixes`, `poe2Jewels`, `poe2Ascendancies` | руны/соул-коры, моды, камни, асценданс |

Риск: при самом первом визите база может ещё не записаться → ждём её появления; без справочника
интерфейс работает, но без подсказок и параметров.

### Ограничения среды
- `curl` блокирует Cloudflare → фикстуры снимаем в настоящем браузере.
- Сайт — SPA: при переходе между билдами без перезагрузки новый `__PRELOADED_STATE__` не приходит →
  догружаем HTML страницы через `fetch` (тот же домен) или перезагружаем.
- Справочник целиком в репозиторий не кладём: в фикстуры идёт выборка только нужных записей.

## Как проходит каждый шаг

1. **Red:** пишу тесты на поведение шага, убеждаюсь, что они падают.
2. **Green:** минимальная реализация, тесты зелёные.
3. **Refactor**, затем `npm test`, `npm run typecheck`, `npm run build` — всё чисто.
4. **Проверка вживую** (где есть UI): открываю билд в Chrome, делаю скриншоты, сверяю с концептом.
5. **Отчёт:** кратко что сделано + что проверить руками. Коммит.

## Шаги

### Шаг 0. Каркас проекта ✅
WXT + TS + Preact + Vitest, `git init`, скрипты `test` / `typecheck` / `build` / `dev`.
Контент-скрипт на `https://mobalytics.gg/poe-2/builds/*` пока только ставит маркер (атрибут на `<html>`).
- Тесты: матчер URL страницы билда (билд / не билд / список билдов / другие игры).
- Проверка: сборка проходит; после загрузки расширения маркер виден на странице.
  Проверяю, работает ли автоперезагрузка расширения при пересборке.
- **Руками (один раз):** `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка сборки.

### Шаг 1. Извлечение данных и фикстуры ✅
- `extractBuildDocument(html | Document)` → `doc` или типизированная ошибка (нет скрипта / битый JSON / нет запроса).
- `readStaticData()` — чтение IndexedDB с ожиданием, базу сайта никогда не создаёт; `pickStaticSubset(staticData, doc)` — выборка нужных записей.
- Дев-экспорт (только в dev-сборке): кнопка в попапе сохраняет `<slug>.json` = `{ meta, build, staticData }`;
  для автопроверок — событие `poe2-build-guide:capture` на `document`, отчёт в атрибуте `data-poe2-build-guide-capture`.
- Фикстуры в `tests/fixtures/` (0.8–1 МБ): Witch Lich, Mercenary Gemling, Ranger Pathfinder; загрузка — `tests/fixtures/load.ts`.
- Тесты на фикстурах: все гемы, уникальные предметы и выбранные ноды дерева есть в выборке справочника.

### Шаг 2. Модель билда и парсер ✅
`parseBuild(doc, staticData | null) → Build` (`src/lib/build/`, модель — `model.ts`): шапка, текстовые секции в порядке
страницы, варианты с экипировкой, скиллами (параметры из справочника), пассивками и заметками автора.
- Вариант по умолчанию — **первый** (как на сайте); id `default-variant` — просто самый старый вариант.
- Моды предмета: реальные значения импортированного → диапазоны аффиксов → диапазоны уникального из справочника.
  Свойства и требования неимпортированных предметов — тоже из справочника.
- Параметры гема: точные на уровне из билда (`statsPerLevel`), иначе диапазоны сайта.
- `priorityList` дерева — все взятые notable/keystone в порядке выбора, а не авторская подборка.
- Имена саппортов без записи в справочнике — из чипов в текстах гайда, иначе из slug.
- Проверено на живой странице: отчёт `poe2-build-guide:parse` и скриншоты сайта совпадают (варианты, шлем, скиллы и саппорты).

### Шаг 3. Rich text (Lexical) → безопасный рендер ✅
`toRichBlocks` (`src/lib/rich-text/convert.ts`) → типизированное дерево; `<RichText>` (`src/ui/rich-text/`) рендерит его
только через JSX. Абзацы, заголовки, списки (в т.ч. вложенные), формат текста, `color: #hex`, переносы,
ссылки (только http(s), относительные → mobalytics.gg, `noopener noreferrer`), чипы сущностей с иконкой (`renderEntity` —
точка расширения для подсказок). Неизвестные контейнеры разворачиваются в абзац.
- CSS UI встраивается строкой (`?inline`) в `createShadowRootUi({ css })`: загрузка CSS средствами WXT (`cssInjectionMode: 'ui'`)
  в dev падала с `Failed to fetch`. Токены дизайна — `src/ui/theme/tokens.css`.
- Dev-модули с Preact/CSS подключать только через `import()` внутри `import.meta.env.DEV`, иначе попадают в прод.
- Проверено: dev-превью (`poe2-build-guide:preview`) на трёх билдах совпадает со структурой текстов на сайте.

### Шаг 4. Монтирование на странице ✅
Контент-скрипт на всём `mobalytics.gg/*`, смена URL — `wxt:locationchange`. UI монтируется в shadow root при первом
заходе на билд (`src/ui/app/mount.tsx`).
- `createBuildLoader` (`src/lib/page/`): билд, с которым открыта страница, — из текущего документа, остальные — `fetch` HTML;
  справочник читается один раз и кэшируется (при неудаче — повтор при следующей загрузке).
- `createPageController`: неактивно / загрузка / готово / ошибка + режим `extension | original`; устаревшие загрузки
  отбрасываются, смена query/hash того же билда не перезагружает. Режим хранится в `storage.local` (`pageModeItem`).
- Оверлей закрывает страницу (`position: fixed`, прокрутка страницы блокируется), в режиме оригинала — кнопка «Открыть гайд».
- Проверено в Chrome: оверлей, «Оригинал» ↔ «Открыть гайд», режим после перезагрузки, переход со списка на билд внутри SPA,
  «Назад»/«Вперёд», ошибка на несуществующем билде.
- Изменение `permissions` в manifest требует ручной перезагрузки расширения в `chrome://extensions`.

### Шаг 5. Дизайн-токены, шапка, вкладки ✅
- Токены — `src/ui/theme/tokens.css`; Inter (latin + cyrillic) встроен в бандл и регистрируется через FontFace API под именем
  `PoE2 Guide Inter`: CSP сайта (`font-src *`) не пускает `data:`, а FontFace из памяти ничего не загружает.
- Шапка по концепту (`BuildHeader`): арт класса, название, класс / асценданс, патч, типы билда, автор, начало Build Overview,
  кнопка «Оригинал». Вкладки (`Tabs`, иконки lucide-preact): WAI-ARIA, стрелки, клавиши `1`–`6` (слушаются в capture-фазе:
  shadow root WXT останавливает всплытие клавиш).
- Маршрут в хэше: **`#gear_act-1`** (`src/lib/ui/route.ts`), без записи в историю (`replaceState`), внешние изменения хэша
  подхватываются. Слэш нельзя: сайт при загрузке делает `querySelector('#toc-item-' + hash + '-id')` и падает на невалидном
  селекторе (проверено: `#a/b` → «Oops, something went wrong»).
- Панели вкладок — пока заглушка «Раздел появится в следующих версиях».
- Доработки по отзыву: шапка сворачивается в компактную строку (кнопка со стрелкой, `aria-expanded`, настройка
  `headerCollapsed` в `storage.local`, общая для вкладок, сохраняется при переходах между билдами); скроллбары UI —
  `::-webkit-scrollbar` в палитре (стандартный `scrollbar-color` на Windows оставляет стрелки).

### Шаг 6. Подсказки (tooltip) ✅
- `build.entities`: чипы из текстов гайда, разобранные через справочник (гем / пассивка / руна / предмет); удалённые из игры
  сущности остаются чипом без подсказки.
- `src/lib/tooltip/`: `TooltipModel` из предмета, гема, пассивки, руны (как в игре: класс, свойства, требования, описание,
  эффекты, бонусы качества, flavour, Corrupted, пометка «диапазоны»); `placeTooltip` — снизу → сверху → справа → слева, в пределах экрана.
- `src/ui/tooltip/`: один `TooltipProvider` на представление билда, `WithTooltip` — задержка 150 мс при наведении, сразу при
  фокусе, Escape/blur/прокрутка закрывают, `aria-describedby`.
- Overview пока показывает тексты гайда с подсказками на чипах (остальное — шаг 9).
- Проверено в Chrome: подсказки Contagion, Atziri's Disdain, Eternal Life, Tecrod's Gaze совпадают с подсказками сайта.

### Шаг 7. Вкладка Gear ✅
- `VariantPicker` (чипы вариантов, `aria-pressed`) на вкладках с вариантом; выбор пишется в хэш (`#gear_act-1`).

- Доработки по отзыву: без заголовков групп и без заголовка «Gear» — броня крупными карточками, остальное компактной

  на окне 1463×662). Руны в предметах — свои подсказки (вложенные `WithTooltip` через `pointerover`). Заметки автора —
  на всю ширину под экипировкой и приоритетом. Иконки Gear без `loading="lazy"`.
- Вторая доработка: без подписи «Variant»; Gear по концепту — колонка брони + сетка остальных в 2 колонки, растянуты на

  Весь UI на английском.
- Сводка резистов/ES — шаг 11.
- Проверено в Chrome: слоты и приоритет FULL LIFE и ACT 1, подсказка редкого предмета с реальными модами и рунами, смена варианта.

### Шаг 10. Вкладка Passives ✅
- Дерево сайта (WebGL-canvas со своими кнопками зума) остаётся в DOM сайта, но его блок кладётся `position: fixed`
  поверх нашей области (`lib/passives/tree-embed.ts`); переносить узел нельзя — React сайта его перемонтирует.
- Находки: якорь `span[id$="-passive-tree-N"]`, N — индекс варианта; при смене варианта сайт перемонтирует секцию
  (MutationObserver находит новое дерево); вариант переключается кликом по `[role=tab]` сайта, сайт переписывает URL
  и теряет наш hash — восстанавливаем. Canvas создаётся лениво, когда секция видна — прокручиваем к ней (под оверлеем).
  Предок с `container-type: inline-size` делал fixed относительным — на время снимаем. У блока `min-height: 580px` — сбрасываем.
  Tippy-подсказки сайта (z 9999) поднимаем стилем; наши тултипы рендерятся вне `.overlay` (портал), чтобы быть над деревом.
  До гидратации сайт игнорирует клик/прокрутку — повторяем раз в секунду, пока дерево не появится.
- Боковая панель Key Passives: асценданс, пронумерованные ключевые пассивки (иконка, первый эффект, тултип), очки.
- Всё возвращается при уходе с вкладки / в оригинал (стили, container-type, прокрутка). Заметки автора к дереву — в Notes (шаг 12).
- Не сделано из interface.md: подсветка/центрирование ноды по клику в панели (canvas сайта не даёт API).

### Шаг 11. Вкладка Atlas Tree ✅
Вместо резистов/ES (перенесены в «Будущие фичи»). Вкладка после Passives, только если атлас есть хоть в одном варианте.
- Данные: `buildVariants.values[].atlasTree` — `mainTree` и под-деревья (`expeditionTree`, `bossTree`, …) с `selectedSlugs`;
  ноды резолвятся через тот же граф `poe2PassiveSkillsGraph` (второе дерево). Панель: очки + notable/keystone по под-деревьям.
  Ноды boss-дерева в текущих static data отсутствуют — просто пропускаются. Заметок к атласу у вариантов нет.
- Сайт: секция `-atlas-tree-N` есть только у вариантов с атласом — вариант переключаем через вкладки любой секции варианта.
  Высоту задаёт внутренний блок (`min-height: 644px`) — слот ищется до первого блока с min-height и потом не перевыбирается.
- Ленивая загрузка деревьев сайта срабатывает на въезд секции в видимую область: повторы чередуют прокрутку вверх и обратно.
- Проверено: Lich (оба эндгейма, ACT 1 — пустое состояние, переход Atlas → Passives), Pathfinder без вкладки.

### Шаг 12. Progression, заметки к дереву, без Notes ✅
Решения пользователя: вкладку Notes убрали (все тексты гайда уже на Overview), заметки к пассивному дереву —
во вкладке Passives, квестовые награды — в Progression.
- Progression: список стадий (варианты по порядку гайда) · выбранная стадия (описание автора + изменения относительно

### Холодный старт: 403 от защиты сайта (после 1.1.0)
- Жалоба пользователя: свежеустановленное расширение на первом заходе показывало «Couldn't show this build» с 403,
  и билд загрузился только с пятой попытки.
- Причина: сайт стоит за защитой от ботов, которая отклоняет запрос из браузера, ещё не примелькавшегося ей.
  На прогретом профиле тот же запрос возвращает 200 и при `cf-cache-status: MISS`, так что дело не в кэше.
- `createHtmlFetcher` делает до четырёх попыток с растущей паузой (0.7 / 1.4 / 2.8 с), а последнюю отправляет
  с `credentials: 'include'` — с сессией самого посетителя, с которой страница уже прошла защиту.
- Пока идут повторы, плашка загрузки пишет «The site is slow to answer. Attempt N of M…», а не выглядит зависшей.
- Если все попытки упёрлись в 403, текст ошибки предлагает открыть оригинальную страницу и повторить.

### Копирование имени гема и память варианта (после 1.1.0)
- Клик по гему в Active Skills, Gem Priority и в описании скилла кладёт его имя в буфер (`lib/ui/clipboard.ts`:
  clipboard API, запасной путь — скрытое поле и `execCommand`). Плашка «Copied …» держится 2 секунды.
- Клик по строке активного скилла и выбирает его, и копирует имя — это один и тот же жест.
- Выбранный вариант (акт/стадия) запоминается по слагу билда в `local:lastVariants`, не больше 30 билдов.
- Верхняя вкладка запоминается так же, по билду (`local:lastTabs`): раньше она была общей, и новый билд открывался
  на чужой вкладке. Билд, который ещё не читали, открывается на Overview. Общий помощник — `rememberPerBuild`.
- Автор билда может переделать варианты, поэтому хранится и id, и название: сначала ищем по id, потом по названию,
  иначе открываем вариант по умолчанию. Вариант в адресе всегда важнее запомненного.

### Имплициты предметов и длинные названия в Gem Priority (после 1.1.0)
- Имплицит (собственный мод базы: сопротивление кольца, дух амулета, условие чарма) лежит в
  `baseItemType.bakedDescriptions` статики. Сайт печатает строку как есть, вместе с метками классов:
  «Armour: Wand or Staff: Martial Weapon: All: +(10-15) to Intelligence» — проверено на его же тултипе.
- Мы метки срезаем. Их набор закрытый, сверен по всей статике сайта (1157 строк, 861 с двоеточием, из них 609 —
  «Grants Skill»): All, Armour, Body Armour, Boots, Bow, Gloves, Helmet, Martial Weapon, One Hand Mace,
  Quarterstaff, Sceptre, Shield, Spear, Wand or Staff. Строки «Grants Skill» в имплициты не идут — они
  показываются отдельным блоком.
- В тултипе имплицит стоит над роллами. Своей линии ему не нужно: у каждого блока тултипа уже есть верхняя,
  и вторая давала двойной разделитель.
- В Gem Priority длинное название скилла раньше вылезало в соседнюю колонку: строка теперь обрезается

  у него `flex-shrink: 1000` и `min-width: 3em`, так что имя гема режется, только когда от скилла остались
  три буквы. Первая версия с потолком 60% на имя гема резала имена даже при коротком скилле рядом.

### Битые картинки с CDN сайта (после 1.2.0)
- Позже выяснилось, что отказы идут пачками и держатся недолго: в Chrome при открытии страницы 51 картинка из 134
  получила 503, а через минуту те же файлы отдавались (и параллельно, и по очереди, 30 из 30). В Firefox в тот же
  момент всё грузилось при тех же IP, узле Cloudflare и http/3 — разница в том, как браузеры раскладывают запросы
  во времени, а не в сети.
- Повторные запросы пробовали (0.9 и 2.5 с с разбросом) и отказались: решение по просьбе автора откатено, заглушка
  должна появляться сразу. Замеры сохранены на случай, если к идее вернёмся: на Progression из 53 картинок 18
  отказали сразу и все вернулись повтором.
- Что осталось от той работы: отказ, который браузер уже держит в кэше, приходит раньше, чем навешивается
  обработчик `onError`. Поэтому `Icon` дополнительно спрашивает `decode()` — без этого такие картинки висели
  битыми, без заглушки.
- Жалоба: у части предметов пропали иконки. Проверено по кодам ответов: `cdn.mobalytics.gg` отдаёт 503 на часть
  файлов из `assets/poe-2/images/game/` (кольца, амулет, посох, фласка, пояс), а на другие — 200 (шлем, нагрудник,
  иконки скиллов). На самой странице сайта в тот момент было 36 битых картинок из 151, то есть это авария у них.
- `ui/common/Icon.tsx` — общий компонент картинки: при ошибке загрузки (и когда ссылки нет вовсе) остаётся заглушка
  того же размера, а для украшений (арт в шапке, иконка в тултипе, чип в тексте) — ничего.
- Заглушка не пустая, а по смыслу места: броня, оружие, щит, бижутерия, фласка, чарм, гем, пассивка, руна
  (`IconKind`). Для экипировки тип берётся из слота — `slotIconKind` в `lib/ui/slots.ts`.
- Все `<img>` в интерфейсе идут через него, так что верстка не скачет и значок битого изображения не появляется.

  после ревью, unlisted — сразу, а номер версии у дополнения уникален, поэтому код уходит под четвёртым числом
  (`FIREFOX_BUILD=1` → `1.3.0.1`) и `.xpi` прикладывается к релизу этой версии.

## Комментарии (план, 06.10.2026)

Спецификация: [reference/poe2perfect_comments_design.md](../reference/poe2perfect_comments_design.md), эскизы —
`reference/Комментарии к билду …-2.png` (вкладка) и `reference/Снаряжение и комментарии …-1.png` (Gear + панель).
Одна модель данных, два представления: вкладка Comments (сначала) и боковая панель (потом). Ответ — прямо из
расширения (шаг C5a), Open on Mobalytics остаётся.

### Данные (живая проверка, 8 билдов каталога)
- **Seed в документе.** Виджет `NgfDocumentCmWidgetCommentsV1` лежит в `doc.content[]` (не в `data.widgets`).
  `data.isDisabled`, `data.payload`: `resourceId`, `commentId` (пустой), `error`, `page { hasMoreItems, nextCursor }`,
  `data { parentId: null, sortBy: "NEW", limit: 10, comments[] }`; `data.commentsUiCapabilities`:
  `loadingBehaviour: "SHOW_MORE"`, `sorting { enabled, defaultSortingOption: "NEW" }`. Тот же payload лежит
  в запросе state `["ngf-comments", resourceId, "NEW", null]`. Signed-out HTML (наш `credentials: 'omit'`) seed
  содержит; у вошедшего пользователя state пустой (~500 байт).
- **`resourceId` = `"Poe2:UG:" + doc.id`.**
- **Счётчик сайта:** `doc.comments.stats.totalComments` (сайт показывает его в шапке гайда). Считает сообщения всех
  уровней, точная семантика с удалёнными не сходится (sample: 30 при 26 + 3 опубликованных). Показываем как сайт.
- **Состав страницы.** 10 корней + все их ответы первого уровня: на всех 8 билдах сумма `replyCount` корней = числу
  пришедших `depth: 1`. Ответы на ответы (`depth: 2`) в список не входят.
- **Сообщение:** `id`, `parentId`, `depth`, `accountId`, `content` (Lexical `{ root }`), `plainTextContent`,
  `status` (`PUBLISHED` / `DELETED`), `createdAt`, `updatedAt` (сдвигается от голосов — не дата правки), `deletedAt`,
  `deletedByModerator`, `isSpoiler`, `spoilerLabel`, `score`/`upvotes`/`downvotes`, `replyCount`,
  `profile { user { id, username, displayName }, avatar { iconUrl }, avatarFrame, title, commentator }`.
  Удалённое: `status: DELETED`, пустой текст, `profile: null`, `accountId: ""` — tombstone, ответы под ним живут.
  `avatar` у обычных пользователей часто `null` → инициалы.
- **Тело:** узлы `paragraph`, `text` (с `format`), `linebreak`, `autolink` — всё уже понимает наш
  `toRichBlocks` (ссылки через `safeHref`) → рендерим `<RichText>`, `plainTextContent` — запасной вариант.
- **Автор билда:** `doc.author.id` (есть в preloaded state и в фикстурах) = `author.user.id` из GraphQL =
  `accountId` его комментариев — сверено на двух билдах с ответами автора (7 и 4 совпадения). Не по имени.
- **API** (`POST /api/poe-2/v1/graphql/query`, без cookie отвечает 200; схемы input сервер печатает в ошибке валидации):
  - `NgfCommentsQuery` → `comments.comments(input: CommentsListInput { resourceId!, sortBy!, limit!, cursor })`;
  - `NgfCommentRepliesQuery` → `comments.replies(input: CommentsRepliesInput { parentId!, sortBy!, limit!, cursor })` —
    так грузятся ответы любой глубины (проверено для `depth: 2`) и продолжение длинных веток;
  - `CommentsSortBy`: `NEW`, `OLD`, `TOP` (остальные значения — ошибка схемы);
  - ответ — `CommentsPayload` (как seed), `error { code, message, retryAfterSeconds }`;
  - запись: `NgfCreateCommentMutation(CommentsCreateCommentInput { resourceId!, content: Map!, sourceUrl })` и
    `NgfCreateReplyMutation(CommentsCreateReplyInput { parentId!, content: Map!, sourceUrl })`, в ответе комментарий +
    `rejectionReason`; запросы сайт шлёт с `Authorization: Bearer` (`getToken`). Есть ещё Delete и Vote — не берём.
- **Якорь `#comments`.** Каталог сайта ведёт на `/poe-2/builds/<slug>#comments` — у нас это откроет вкладку
  Comments, что и нужно. Community-билды (`/poe-2/profile/…`) расширение не обслуживает — вне объёма.
- **Защита сайта.** Частые запросы HTML без cookie начинают получать 403 (GraphQL при этом отвечал) — лишний раз
  страницу ради комментариев не перезапрашиваем, seed берём из уже загруженного документа.
- **Не проверено:** билд с `isDisabled: true` и билд без комментариев (в каталоге таких не нашлось) — разбираем
  оборонительно, тесты на синтетике; запрос из контент-скрипта (Chrome — обычный `fetch`, Firefox — `content.fetch`)
  проверяем вживую в C3.

### Шаги
- **C1. Исследование и синтетические фикстуры ✅** — результаты выше. `tests/fixtures/comments.ts`: сообщения,
  tombstone, payload, виджет, `withComments(doc)`, ответы GraphQL; `tests/comments-fixtures.test.ts` проверяет,
  что `scrubBuildDocument` их вырезает и разбор билда они не меняют.
- **C2. Модель и разбор seed ✅** (`lib/comments/model.ts`, `parse-comments.ts`). `parseCommentsSeed(doc)`:
  нет виджета / пустой или ошибочный payload → `unavailable` (не ноль), `isDisabled` → `disabled`, иначе `ready`
  с `resourceId`, `sort`, `canSort`, `total` и списком. `parseCommentsPayload(payload, authorId)` годится и для
  страниц API (C3): корни в порядке сайта, ответы по родителю от старых к новым, дубли по id схлопываются, tombstone,
  спойлер с подписью, автор по `doc.author.id`, аватар только https, мусорные записи пропускаются.
  `LoadResult` несёт `comments` рядом с `build`. **Edited не показываем:** `updatedAt` сдвигается от голосов
  (у всех 58 проголосованных из 247 комментариев), признака правки у сайта нет.
- **C3. Источник и контроллер ✅** (`lib/comments/source.ts`, `controller.ts`). Источник: `NgfCommentsQuery` и
  `NgfCommentRepliesQuery` через `pageFetch` (same-origin), ошибки сведены к `{ message, retryAfterSeconds }`
  (`HTTP 429` + Retry-After, код сайта, `network error`, `unexpected answer`), отмена — AbortError. Контроллер на
  билд: первая страница из документа, `loadMore`, `loadReplies` (ответы от старых к новым, в т.ч. второй уровень),
  `setSort` (лист меняется только по приходу новой страницы, страницы старого порядка отбрасываются), `retry` для
  `unavailable` (первая страница через API), `dispose`; один запрос на вид, без повторов до `retryAt`.
  Seed `unavailable` теперь несёт `resourceId`/`authorId`/`total`. Живая проверка в Chrome (dev-хук
  `poe2-build-guide:comments`): sample build — 10 → 18 корней, ответ второго уровня догружен; билд с ответами
  автора — 14 его сообщений распознано. Firefox — проверить руками.
- **C4. Вкладка Comments ✅** (`ui/comments/`: `CommentsPanel`, `CommentThread`, `CommentCard`, `use-comments`,
  `comments.css`; `lib/comments/time.ts`). Вкладка последней, всегда видна, вариант не сбрасывает, `#comments`
  с сайта её открывает; в табе — счётчик сайта. Контроллер комментариев создаёт `PageController` на каждый
  загруженный билд и закрывает при уходе. Карточки по эскизу -2: аватар / инициалы, имя, Build author, «2 hours ago»
  (полная дата в title), тело через `<RichText>` (в комментариях бывают чипы предметов) с запасным plain text,
  складывание после ~8 строк, спойлер под кнопкой. Удалённые — как у сайта: без ответов не показываются, с ответами —
  «This comment was deleted by its author.» / «…removed by a moderator.». Ветки открыты сами до третьего уровня
  ответов (по замечанию пользователя), глубже — View N replies; свернуть можно у корня (Hide replies). Недостающие
  ответы открытых веток догружаются сами, дальше — Load more replies; ответ на ответ —
  на том же отступе с «Replying to @name» (кнопка к родителю); у ветки — Author replied. **Сюда же из C6:**
  Load more comments и ошибки страниц (с «The site asked to wait N s.»). Состояния: No comments yet, disabled,
  unavailable (+ Try again через API), Loading comments…. Проверено вживую: 10 → 20 корней, ответ автора с бейджем
  и линией, второй уровень ответов.
- **C5. Переход на сайт ✅** (`lib/page/original-comments.ts`). «Reply on Mobalytics» в подвале вкладки (и при
  пустом списке), «Open on Mobalytics» в состоянии unavailable; disabled — без кнопок. Режим original в той же вкладке
  (ArrowUpRight), затем `revealOriginalComments`: ждёт `[data-testid="comment-widget-general"]` до 5 с
  (MutationObserver), прокручивает окно так, чтобы верх виджета был в 72 px от края (липкая шапка сайта — 56 px),
  для Reply ставит курсор в поле сайта (`role=textbox`, есть только у вошедших) — ничего не пишет и не отправляет.
  Open guide возвращает на Comments (hash не меняется). `Open thread` не делаем: `data-id` комментариев в DOM сайта
  то есть, то нет между загрузками — надёжного якоря ветки нет.
- **C5a. Комментарии и ответы из расширения ✅.** Авторизация — сессионная cookie посетителя, не токен: в браузере
  GraphQL-клиент сайта шлёт `Authorization` только в десктопном приложении (`IS_DESKTOP`), а «Bearer» в бандле — это
  Firebase. Проверено безвредной мутацией снятия голоса с несуществующего комментария: без cookie —
  `FORBIDDEN: not authenticated`, с cookie — `NOT_FOUND`. `content` — Lexical как у редактора сайта (абзац на строку,
  у paragraph `textFormat`/`textStyle`), снято с тестового комментария пользователя; `sourceUrl` — адрес билда без hash.
  `source.post` (`NgfCreateCommentMutation` / `NgfCreateReplyMutation`), `controller.post` (свой комментарий — первым,
  ответ — в конец ветки, счётчики +1; `FORBIDDEN` → signed-out, `rejectionReason` → rejected, задержка сайта).
  UI: поле «Add a comment» одной строкой над списком, Reply у каждого живого комментария открывает поле под ним (одно
  за раз, фокус, Cancel / Escape), отправка только кнопкой или Ctrl+Enter, лимит 1000 символов, текст не пропадает при
  ошибке; не вошёл — «Sign in on Mobalytics to comment.» с переходом на сайт. Кнопка в подвале — «Open on Mobalytics»
  (без фокуса в поле сайта). Живую публикацию из расширения проверяет пользователь.
- **C6. Навигация по обсуждению ✅** (`lib/comments/filter.ts`, панель). Бесконечная прокрутка (по просьбе
  пользователя) вместо Load more: маркер конца списка + IntersectionObserver (корень — список, запас 400 px),
  наблюдатель пересоздаётся на каждой новой странице; при ошибке — без автоповтора, Try again. Сортировка Newest /
  Oldest / Top (select, во время загрузки показывает выбранное, при ошибке — «Couldn't sort the comments»), скрыта
  при `canSort: false`. Поиск по загруженным текстам и именам (`filterThreads`): ветки с совпадениями, путь к
  совпавшему ответу раскрывается поверх свёрнутого, подсветка — CSS Custom Highlight API (`::highlight()` в стилях
  shadow root, текст не трогаем). Чипы All comments / Author replied (`aria-pressed`), скрыты без
  `canIdentifyAuthor`. При поиске/фильтре сама не грузит: «Searching loaded comments only (N of M). Load more»,
  пусто — «No matches in loaded comments». Пока поиск или фильтр включены, недостающие ответы догружаются для всех
  загруженных веток до глубины автораскрытия (иначе ответ автора глубже первого уровня в скрытой ветке не находился). Проверено вживую; в фоновой вкладке автоматизации наблюдатель молчит,
  пока браузер не рисует кадры (`visibilityState: hidden`) — в обычной вкладке работает.
- **Лента вместо карточек (по замечанию пользователя: «читать как ленту на треде», как Reddit) ✅.** Шапка — одна
  строка ~40 px без заголовка (название и число — на вкладке): чипы, поиск 200→260 px при фокусе, сортировка
  текстом (Newest / Oldest / Top), иконка Open on Mobalytics; шапка и поле ввода — первые элементы прокручиваемого
  списка и уезжают вместе с лентой; подвала нет — список на всю высоту.
  Колонка до 960 px; комментарии без рамок, ветки разделены тонкой линией, аватар 28 / 24 px, «имя · время» в строку,
  действия серые 12 px (акцент — только у автора и у кнопок восстановления), ответы висят на линии от центра аватара.
  Текст комментариев и поле ввода — шрифт для чтения Noto Sans 15/23 px (`--font-reading`, `@fontsource-variable/
  noto-sans`, латиница + кириллица, регистрируется как Inter через FontFace, +~75 КБ в base64), интерфейс — Inter.
  Эскизы -1/-2 в этой части больше не эталон.
- **Ветки как на Reddit ✅.** Ответы по-настоящему вложены (подпись «Replying to» убрана): от аватара вниз идёт
  линия, к каждому ответу — скруглённый «локоть», линия заканчивается на последнем ответе. Сворачивание — кружок
  −/+ на линии (`aria-label` Hide replies / View N replies) или клик по самой линии; у каждой открытой ветки свой.
  Сортировка — своё меню (`SortMenu`, listbox: стрелки, Enter/Space, Escape, клик мимо) вместо нативного select,
  выпадающий список которого рисовался в системном стиле.
- **Голоса ✅** (по просьбе пользователя; в спецификации были отложены). `score` и `viewerVote` в модели,
  `NgfCommentVoteMutation { commentId, value: UPVOTE | DOWNVOTE }` и `NgfCommentDeleteVoteMutation { commentId }`
  (схема — из ошибки валидации, значения — из бандла, проверено на несуществующем комментарии). В строке действий
  ▲ счёт ▼: голос виден сразу, затем — числа сервера; при отказе откат и «Sign in on Mobalytics to vote.».
  Ограничение: первая страница читается без cookie, поэтому уже поставленный раньше голос на ней не подсвечен.
- **Линии веток тоньше и с подсветкой ✅.** 1 px, «локоть» точно на линии родителя; наведение на линию или кружок
  подсвечивает её и «локти» к прямым ответам (`:has()`, переменные `--rail` на комментарии и `--branch` на блоке ответов).
- **C7. Боковая панель.** Кнопка в правой части tab bar (`Open/Close comments panel`, `aria-expanded`), ≥ 1180 px,
  ширина `clamp(360px, 32vw, 480px)`, `aside` со своей прокруткой; тот же контроллер и состояние (поиск, ветки).
  Сначала Gear (панель вместо Gear Priority через явный layout-prop, предметы в две колонки), затем Skills и Overview.
  Passives / Atlas Tree / Progression в первой версии ведут на вкладку Comments — деревья не ужимаем.
  Expand → вкладка + Back to <раздел>; X и Escape закрывают, фокус возвращается на кнопку; уже 1180 px — переход
  на вкладку. Сверка с эскизом -1.
- **C8. Проверка и выпуск.** Firefox, клавиатура, длинные ветки, переключение билдов, 1280×720 / 1920×1080 / 125 %,
  README и CHANGELOG.

Упрощения против спецификации (сознательно): без отдельной таблицы capabilities сверх реально найденных флагов,
без Refresh и восстановления якоря чтения при смене ширины в первой версии, вложенность — два уровня, как у сайта.

## Будущие фичи

### Резисты и ES (beta)
Расчёт по предметам (моды уникальных — диапазон мин–макс, моды рар из билда) и пассивкам
(`bakedDescriptions`). Вывод в сводке Gear с пометкой **beta** и подсказкой «приблизительно».
- Тесты: разбор строк модов (`+(20-30)% to Fire Resistance`, `+X to maximum Energy Shield`, `% increased`),
  суммирование, неизвестные моды игнорируются.
- Проверка: сверка с Path of Building / калькулятором на одном билде (если есть PoB-код в гайде).
